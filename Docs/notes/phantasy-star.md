## SEGA AGES ROM analysis (done 2026-11-11)

`Phantasy Star (World) (En) (Sega Ages).sms` (540,672 B = 33 banks) is **Rev A + FM sound only**, no gameplay/QoL changes:
- Banks 0-31 identical to Rev A except **28 bytes in bank 0**: `$0010-$0025` (was `$FF` padding) holds a stub that does `... out ($F2),1` (enable the YM2413 FM unit) then `jp $02ED`; `jp $02ED` at `$00A2` became `jp $0010`; the 4 sound-call shims at `$02E9/$02EB/$02F1/$02F9` select **bank `$20` (new bank 32) and entry `$8052`** instead of bank 12 / `$8043`.
- Bank 32 (16 KB, at `$80000`) = a new sound driver (channel structs at `$C00E`, 10 channels = 6 FM melodic + rhythm + 3 SFX slots) that writes the YM2413 via ports `$F0` (reg) / `$F1` (data) / `$F2` (control).
- So the AGES soundtrack = FM music AND FM sound effects (measured 2026-11-14: the PSG is never audible in FM mode; SFX play on FM channels 4/5). Everything else (game logic, graphics) is the original code.

## Dungeon map: stairs / exits used = visited, wrong layout on entry (2026-11-24, user report; NOT committed yet)
User report: (1) stairs used (entering / leaving the cave, between floors) were never shown as visited (only
cells the party stood on are; a pit is stood on, so it was); (2) the cells around the stairs the party
arrives by were missing, but showed on the second entry into the same cave.
- Facts (ps1.asm): stairs and doors move the party 2 cells (`LABEL_6731`: position += 2 steps, facing kept),
  so it never stands on them and the passage is always the cell right behind it after arriving. All 44
  dungeon entrance records (type `$0A`, `LABEL_78BD`) put the party on a floor cell with the exit (nibble
  `A` / `B` / `C`) directly behind it, facing away (checked with a script over the entrance lists).
- Cause of (2): entering a dungeon sets `Dungeon_index` first while RAM `$CB00` still holds the PREVIOUS
  dungeon's layout for some frames; the map recorded that first frame (stable hash) with the wrong layout,
  so "is the cell behind a passage" read another floor (and the wrong cells were stored). The second entry
  into the same cave found its own leftover layout, so it worked.
- Fix (`Common/sms/PhantasyStar/ps_automap.c`): `load_layouts()` finds B15_DungeonLayouts in the ROM by the
  first floor's bytes (all 17 PS ROMs: file `$3DF6E`); `layout_match()`; nothing is recorded until >= 224 of
  256 cells of `$CB00` (low nibble) equal that floor's ROM layout (doors / chests change a few). Passages
  used get VISITED + their 3x3 revealed (`mark_used`): on arrival from outside the exit behind (only if it is
  an exit: cell bit 3), after stairs the stairs behind (only when the position changed: a pit keeps it), a
  door walked through (2-cell jump, as before + now VISITED); when leaving a floor by stairs the stairs ahead
  of the last cell (not when the last cell is a pit); when leaving the dungeon the exit ahead (`mark_ahead`).
- Verified (Rev A, `PS_AUTOMAP_ASCII=1` dump, which now also prints the visited cells): Triada Prison, then
  Medusa Tower 1F (was: wrong cells `l` / `o`, no exit; now: exit `d` behind + surroundings, E8 visited);
  1F `45` -> stairs `35` -> 2F `25` (stairs `35` visited + 3x3) -> turn -> back down (1F `35` visited +
  3x3); entering facing south + leaving through the door: `E8` marked on leaving; dungeon soaks 20000
  frames Rev A (floor 04) + Japan (floor 1D): 0 misses, 0 `[stack]`. All 17 PS builds relinked.
- Test recipe: `ps_scenario.py <out> --map 0 --level 30 --items 0` (items 0 = has the light: Medusa Tower is
  pitch black otherwise, "CANNOT GO FORWARD"), keep its press lines < 4500, add pokes `F:C30D=<floor>`,
  `F:C30C=<cell>`, `F:C30A=<facing>`, `F:C202=0A` (= what an entrance does), then presses (U forward, L / R
  turn, A opens a door). Floor layouts: `Tools/sms/ps_dungeons.py`, `ps_draw_floors.py`.
- Pitch-black floors (2026-11-24, user chose "map only what the party walks on"): tested in the game, the
  party never walks in the dark. GameMode_LoadDungeon: no Magic Lamp ($39) and the floor not in
  LABEL_6DFE (lit without it: $01 $02 $14 $15 $16 $21) -> LABEL_6D7F leaves `$C315` = 0 (else palette + 1),
  the screen stays black, "CANNOT GO FORWARD, IT'S PITCH BLACK.", the player menu opens (LABEL_1BE1);
  FLASH ($27, ItemUse_Flash) sets `$C315` = $FF and the floor is lit, otherwise Game_mode = LoadMap (back
  outside). `$C315` stays nonzero inside a dungeon (stairs keep it), LoadMap clears it. Before, the map
  recorded the entrance, its 3x3 and the view ahead of that refused entry. Now ps_automap.c counts the
  party as in a dungeon only while `$C315` != 0 (same code / address in all 17 ROMs: pattern
  `3E 39 CD .. .. 20 05 3E FF 32 15 C3`). Tested (Rev A floor 00 pos 15): dark + cancel = nothing
  recorded, back on the map; lamp = recorded as before (exit $14 visited); dark + FLASH = lit, recorded
  with the exit. Soaks 20000 frames: Rev A + Japan (lamp), PSRP EN + Korea (no lamp): 0 `[stack]`, 0
