## Everyday commands (OLD per-game dir `PhantasyStarSMSRecomp/`, kept for reference)

**To just play:** `PhantasyStarSMSRecomp/play.ps1` (Rev A, PSG) or `PhantasyStarAgesRecomp/play.ps1` (AGES ROM, FM music). Both need `build/` (see build commands below) and the ROM copy in the game dir.


```powershell
# Build the recompiler once (from smsggrecomp/recompiler): cmake -S . -B build -G Ninja ... ; cmake --build build
./run_loop.ps1 [-Frames 3600]   # regenerate C from game.toml -> build runner -> run headless -> print dispatch misses
./build.ps1 -Framework ..\smsggrecomp -SkipRegenerate -Jobs 4        # just rebuild runner
build\PhantasyStarSMSRecomp.exe ..\phantasystar.sms --window 3        # play (window title is still hardcoded "Sonic 1 (SMS)")
# Headless verification vs the pure interpreter (ground truth):
build\PhantasyStarSMSRecomp.exe ..\phantasystar.sms --frames 1500 [--interp] --dump-frame 1499 --dump-out d.ppm --report r.json
#   dump file is actually a PNG; .cram/.vram/.ram/.regs siblings are raw -> compare recomp vs --interp.
```

### Diagnostic build + differential harness (very useful)
`build_diag/` = reference execution, no GPU, `-DSMS_TRACE_PC`:
```
cmake -S . -B build_diag -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=C:/msys64/mingw64/bin/gcc.exe \
  -DCMAKE_MAKE_PROGRAM=C:/msys64/mingw64/bin/ninja.exe -DCMAKE_PREFIX_PATH=C:/msys64/mingw64 -DSMSGG_ROOT=<abs path to smsggrecomp> \
  -DSMSGG_REGENERATE=OFF -DSMSGG_NATIVE_EXECUTION=OFF -DSMSGG_ENABLE_GPU=OFF "-DCMAKE_C_FLAGS=-DSMS_TRACE_PC"
```
Env vars (run `build_diag\PhantasyStarSMSRecomp.exe ..\phantasystar.sms --frames N`):
- `SMS_RAM_WATCH=<hexaddr>|ALL` + `SMS_RAM_WATCH_FRAME=n` -> log writes with call chain.
- `SMS_DIFF_ADDR=<hex,hex,...>` (<=256) + `SMS_DIFF_LO/HI=<frames>` + `SMS_DIFF_MAX=1` -> per-function recomp-vs-interpreter state diff; prints `DIVERGES` with regs/RAM.
- `SMS_DIFF_TRACE=1` -> also pinpoints first divergent instruction / prints stream tails (I added the tails print in `runner/glue.c`).
The function list for SMS_DIFF_ADDR: `grep -o -E "func_[0-9A-F]{4}" generated/ps1sms_funcs.h`.


## Useful / ruled-out links (checked 2026-11-12)  *(part; the rest of this section is in another notes file)*

- **Workflow gotchas (2026-11-12):** (a) only ONE ninja per build dir: a second start fails with "failed recompaction: Permission denied" (use another `-Build <dir>`); (b) `check.ps1` aborts on the runner's stderr (PowerShell NativeCommandError): for regressions run the exe directly (`SMS_NO_SAVE=1 exe ROM --frames N --press-file ...`); (c) a `( ... ) &` wrapper task reports "completed" immediately, the real job keeps running - wait on a log file/`done` marker with Monitor; (d) the runner now prints, when the reset routine returns (stack unwound too far): last 48 function entries + the stack memory below SP - the first thing to read for "run stops early" bugs; (e) VDP-log compare recomp vs `--interp` (`SMS_VDPLOG`): ignore frame numbers, pushed-AF flag bytes and the interrupted-PC word, they differ by timing only.
## Correctness testing (2026-11-12 night) - READ THIS
- **Engine bug found + fixed (all PS builds were affected since the start):** `ld de,cont ; push de ; call LABEL_787B` where `787B` ends `pop hl ; ret` (drops its own return address, RETs into `cont`). Used by GameMode_LoadShip/LoadRoad/`$0A74` (ship, landrover, road map loading) and 2 more sites. Old code returned out of the caller (stack leak, skipped map load; forced LoadShip/LoadRoad diverged from `--interp`, ending in mode 3 on a garbage screen). Fix: `trace_push_call()` in function_finder.c (+ codegen in `emit_call_target`: `if (sp - _csp == 2) goto L_cont`), and `trace_ret_jump`/`trace_computed_call` ignore a push that feeds such a call (the Golvellius ret-jump code had mis-read `$0ABE ret` as a computed jump).
- **New runtime guard:** generated code calls `sms_call_unbalanced(at)` when a CALL returns with SP *below* its pre-call value -> `[stack] call at 0x.... returned with SP below ...` on stderr (once per site). Any such line = a stack-model bug to investigate.
- **Runner fixes/additions:** press table was capped at 1024 directives (the `rand*.txt` files have ~3900, so earlier "60000-frame soaks" only had input for ~15000 frames) -> now growable + sorted/cursor; `--poke-file` (FRAME:ADDR=VAL per line); env `SMS_COVERAGE=<file>` (executed function entries, analyse with `python -I Tools/coverage.py <slug> <files...> [--list]`); env `SMS_STATE_LOG=<file>` + `SMS_STATE_EVERY=N` + `SMS_STATE_SKIP=lo-hi` (RAM/VRAM/CRAM hash per N frames, works with `--interp`).
- **Lockstep test = the "100%" metric:** `sh Tools/lockstep.sh <slug> <outdir> <frames> <press> [poke]` runs recomp and `--interp` on the same input and compares the hashes. PS is frame-locked, so they stay identical; isolated single-checkpoint differences that reconverge are interrupt-timing noise, a long run / final mismatch is a real bug. Rev A: 60000 frames of `rand1.txt` -> final state identical.
- **R register = legit timing input:** PS `UpdateRNGSeed` returns `ld a,r ; xor l`; R counts every instruction incl. the VBlank busy-wait, so recomp (IRQs at sync points) and `--interp` (cycle exact) get different random numbers -> battles diverge without any miscompile. Test-only env `SMS_FIXED_R=1` (default in `Tools/lockstep.sh`): LD A,R returns a hash of its own execution count, in both builds (`sms_test_r()` in glue.c; hooked in codegen and in the vendored superzazu `z80.c` - the only local change to that file). Golvellius (18x `ld a,r`, reads V-counter `$7E`) and Sonic 1 still drift (from frame ~180 / ~2160, `$C007` off by one): most likely the same kind of timing input in an idle loop, NOT analysed yet.

- **Golvellius drift analysed:** from frame ~127 the recompiled build takes the VBlank IRQ at a slightly different point (it is inside the IRQ handler's unrolled `outi` VRAM copy at the frame boundary, the interpreter is not), so its frame counter `$C007`/`$C83A` runs one tick ahead. ## Gotchas learned

- The engine keys code by `(bank, addr)`; `[jump_tables] bank` is the bank mapped at that address (slot-2 tables use the slot-2 bank, e.g. 12 for `$82E5`).
- "entry trail" addresses in `dispatch_misses.log` are function entry ids (e.g. `0008` = `rst_08` VDP-address helper), not necessarily where the bad jump came from.
- After editing the recompiler: rebuild `smsggrecomp/recompiler/build`, then `run_loop.ps1` (it regenerates). Never edit `generated/*.c`.
- Python/heredoc edits of C source: `\n` inside C string literals gets mangled; prefer the Edit tool.
