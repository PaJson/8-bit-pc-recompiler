## Multi-ROM workflow (2026-11-12)

One recompiled build per ROM, each in `Games/<slug>/`, made by a generator so it is reproducible:
```
python -I Tools/mkgame.py <slug> "<file in ROMs/<platform>/>" "<window title>" [--platform sms] [--template ps_reva|sonic1|sms_generic] [--hooks ps|none]
        [--auto-tables]                     # PS only: detect [jump_tables] with Tools/ps_find_tables.py
        [--byte-table ADDR:BANK:COUNT:PAGE] [--table-count ADDR=N] [--banked ADDR:BANK]
Games/sms/<slug>/build.ps1                  # recompile ROM -> C, build the runner (needs recompiler/build/SmsRecomp.exe)
Games/sms/<slug>/check.ps1 -Frames 20000 -Press ..\..\..\Tools\test_input\rand1.txt   # headless soak, lists dispatch misses
Games/sms/<slug>/play.ps1 [-Scale 3] [-Speed 1.0]   # saves go to Games/sms/<slug>/saves/ (env SMS_SAVE_DIR, new)
sh Tools/verify_game.sh <slug>              # build + compare recompiled vs --interp frames on a scripted input
```
`game.toml` `rom = "../../../ROMs/sms/<file>"` (relative to the game folder; `CMakeLists` default `SMSGG_ROOT = ../../../Recomp/smsggrecomp`).
Every generated build is tied to its ROM's CRC32 (the runner refuses another ROM). Launcher app: see "Launcher" in the QoL / feature ToDo below.

**Path gotcha:** the project path (`...\VS2026\Projects\8-bit-PC-Recompiler`) no longer has spaces or `#` (folders moved / renamed 2026-11-22 and 2026-11-23). Still quote paths in scripts (other machines / clones). Folder depth matters: game folders are 3 levels below the root (`Games/sms/<slug>`).

## Recompiler review (2026-11-15, Opus pass over the idiom code)
- **Fall-through gaps (fixed):** the emitter writes instructions in address order and never checked that the next one is the Z80 successor. A trace with overlapping decodes (a jump target inside an instruction, almost always from data decoded as code) or a trace that stops early ran on into the wrong C code. Example found in the generated code: Golvellius bogus `func_3878` (reached from data in bank 5: `jp m,$3878`), `$38AB ld hl,$3972` ran on into `$38AC ld (hl),d ; add hl,sp` (= the real code's operand bytes), so `call $3992` got a wrong HL (the real copy of that code, inlined elsewhere, was fine). Now `fallthrough_gap()` (code_generator.c) emits `goto L_<succ>` / `call_by_address(succ); return;` there; summary line `[cg_emit] N fall-through gaps`, list with `SMSREC_GAP_LOG=1`. Counts: PS Rev A / USA / Brazil / AGES / Japan / Japan Rev 1 / EN 2.5 0 (generated C byte-identical), Korea 3, Miracle Warriors 1 (bogus `rst_28`, never run), ps-ja-smspower 10, Sonic 2 11, Golvellius 446 (74 addresses in bank-5 data-as-code + 6 others). Every case checked was in data decoded as code / a bogus entry.
- **Stack scans (hardened):** the backward push/pop scans (`trace_computed_call_push`, `ret_jump_scan`) now give up at `ex (sp),hl/ix/iy` and `ld sp,(nn)` (they ignored them: a wrong continuation would have been possible); the stack dataflow also treats `ld sp,(nn)` as unknown. No generated C changed in any build.
- **Not changed (design limits, never hit):** (a) the call contract decides "returned normally / dropped its return / unwound" from SP alone: a callee that removes its caller's pushed argument (callee-clean) would be mis-handled. All `push rr ; call F` sites (PS 5-11 per ROM, Golvellius 18, MW 3) have callees that return normally. A robust variant would compare the word below SP after the call (the address the RET used) with the return / continuation address. **Static check (`python -I Tools/stack_shapes.py Games/<slug>/generated/*_full.c`)**: follows every path of every recompiled function and lists each pop / `ex (sp)` / `inc sp` of a word the function did not push itself, grouped by the instructions that follow. PS Rev A / Japan / Korea / AGES En / EN 2.5, Miracle Warriors, Golvellius: 37-59 sites each, all of kinds the call contract handles: drop own return (`pop hl ; ret` = PS LABEL_787B, `pop hl ; jp X`), abort N frames (`pop hl ; pop hl ; ret`, PS battle `pop hl ; pop bc ; jp`), inline data after the call (EN 2.5 bank-29 text decoder `pop hl ; push bc ; ... ld a,(hl)`: continues by a tail jump, the caller then propagates), shared interrupt epilogues, `ex (sp),hl ; ex (sp),hl` delays (MW, Golvellius). **No callee-clean routine** (pop return ; pop argument ; push return ; ret) in any of them. Run it on every NEW game: such a routine would need the robust variant above. Limits: only recompiled (traced) code, depth per instruction from the first path that reaches it. (b) Bogus functions from data decoded as code (Golvellius bank 5, `func_3878`, Korea `func_6900`, MW `rst_28` = mid-instruction vector) only cost code size; what seeds them is not analysed.
- Checked and fine: bank resolution of direct calls (SMS_CALL_BANKED falls back to the runtime bank), the propagation guards after calls / computed calls / trampolines, the path-dependent push handling (G_AMB), the stack dataflow (claims only when all paths agree).
- Hook / runtime review (same day): FLY, quick vehicles, damage, EXP, battle auto attack, hovercraft, ITEMS, SOUND CHIP hooks: offsets and flag contracts match the patterns in Tools/ps_find_hooks.py (resume offsets are relative to the hook address).
